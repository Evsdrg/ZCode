# Fork 发布与仓库卫生

状态：已实施

## 发布规则

- 公开分支基于当前官方源码基线，按功能提交源码、测试、依赖锁、产品spec和匿名化的维护文档。
- 私有运维记录、具体公网/mesh地址、主机名、账号、真实工作区列表和会话内容留在忽略的 .local/ 或 docs/local/，不进入公开分支及其新增提交历史。
- 旧本地工作分支保持不变；存在部署身份信息的本地提交不cherry-pick、不push --all。发布使用单独的 selfhost/maintained 分支，不覆盖fork main、不force push。
- 用户明确授权的fork推送仅包含核对过的单一分支；官方origin保留为上游，fork单独配置remote。

## 跟踪范围

- 保留官方提供的公共env模板、架构skill、编辑器公共配置及必要类型声明。不能以开发产物为由删除有源码依赖的上游文件。
- gitignore覆盖本地env/凭据/密钥/会话状态、下载或构建目录、日志、抓包、GUI验收截图、临时探针、部署备份及私有文档。
- .gitignore不清除已有提交；历史隔离由发布分支构造保证，候选文件与新增提交逐一检查。
- publish:check读取git文件集合，只打印问题类型/文件/行号，绝不打印命中的值。检查新增敏感字面量和私有部署身份，以及误入索引的运行产物。
- 手工审查补充自动扫描；扫描通过不表示所有敏感信息都能被正则识别。

## 修改维护分类

- 小型上游修复使用独立功能提交，可cherry-pick或git format-patch导出；源码为唯一事实源，不重复提交整套应用patch文件。
- 服务装配、平台能力策略、依赖与持久化接口保持源码修改，与新增模块一起验证。
- relay、托管浏览器、文件上传store、Controller、测试基建为新增模块，不归类为二进制patch。
- pnpm patchedDependencies仅用于第三方依赖补丁，现有上游patches/不改变。
- 系统服务、官方闭源Agent制品、凭据与数据库迁移属于部署层状态，不复制进源码fork。

## 验收

1. 本地.env/credentials/密钥/会话日志/GUI截图/探针/私有文档命中忽略规则；真实源码/spec/test/公共env模板不被误忽略。
2. publish:check能拦截字面量令牌/私钥/JWT/部署账号或地址，输出不含凭据；扫描真实候选通过。
3. 官方origin/main是发布历史祖先；旧运维记录提交不是祖先；发布分支最终源码与本地整理源码一致。
4. 类型检查、lint、架构检查与各包测试真实执行；已有警告/全仓格式基线如实说明。
5. 推送后远端分支SHA与本地提交一致；工作服务不重启，真实数据不修改。
